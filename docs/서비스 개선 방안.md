# 서비스 개선 방안

> 기준 문서: **[서비스 정의.md](서비스%20정의.md)** — 모든 기능은 그 문서의 한 문장과 두 층 구조에 대조하여 채택/보류한다.

서비스는 세 화면으로 구성되며, 이는 하나의 루프다.

```
순위(발견) → 차트(분석) → 회고(학습) → 다시 발견
```

각 단계에서 사용자가 아직 직접 하고 있는 일을 시스템이 대신하는 것이 개선의 기준이다.

---

## 1. 차트 — 박스에 서사 입히기

### 1-1. `BaseItem` 확장

백엔드는 `stageLevel`, `stockBaseKind`(BASE/PULLBACK), `isVcp`, 라인 강도를 이미 계산하지만, `BaseListResponse.BaseItem`은 기간·지지·저항 4개 필드만 내려준다. 가장 값진 계산 결과가 API 직전에서 소실되는 상태.

- `BaseItem`에 `stageLevel`, `baseKind`, `isVcp` 추가
- 프론트는 박스 위에 라벨 렌더링: **"2단계 · VCP 응축중"**
- 계산은 완료되어 있으므로 DTO 필드 추가 수준. **작업량 대비 효과 최대**

### 1-2. 자리(위치) 지표 — `StockRegimeResponse` 확장

현재 응답(regime, support, resistance, 기준선 대비 변화율)에는 매매 결정에 필요한 숫자가 없다. 추가할 세 가지:

| 숫자 | 의미 | 계산 근거 (기존 보유) |
|---|---|---|
| **피벗(진입 기준가)** | 돌파가 유효해지는 가격 | `strongestResistanceLine`의 `getUpperBound` |
| **확장도(extension)** | 현재가가 피벗에서 몇 % 벌어졌나 | 현재가 vs 피벗 |
| **리스크 %** | 지금 진입 시 손절선까지 몇 % | 현재가 vs `lowestSupportLine` |

`BREAKOUT_SUCCESS`라는 단어 대신 "피벗 36,100원 대비 **+13.7% 확장**, 손절선까지 **-19.6%**"를 보여준다. 숫자 자체가 답이 되어, 조언 없이도 사용자가 스스로 판단하게 된다. 특히 **확장도**는 "돌파했나"(이미 앎)가 아니라 "얼마나 멀리 왔나"에 답하는, 현재 서비스의 가장 큰 구멍이다.

추가 후보: MA 이격도, 52주 신고가 근접도(→ 7-2 참조).

---

## 2. 시장 컨텍스트 — "시장이 좋은가"

현재 지표는 전부 종목 단위다. 판단 오류의 상당수는 "종목은 맞았는데 시장이 무너지는 중에 샀다"에서 온다(CANSLIM의 M). 시장 상태가 기록되지 않으면 회고에서 "내 셋업이 나빴는지, 그 주에 지수가 빠졌는지"를 영원히 구분할 수 없다.

- 지수(코스피/코스닥)의 MA 상/하 여부, 단기 추세 — **2~3개 값이면 충분**
- 서비스 진입 화면(순위)에 시장 상태 배너로 노출
- 스냅샷 동결 항목에 포함(→ 5번)

## 3. 시그널 검증 — 프로젝트의 논리적 척추

### 왜 필수인가

지표 축(RS, FIP, 모멘텀 등)은 논문이 근거를 댄다. 그러나 서비스의 심장인 **베이스 엔진**(베이스 감지, stageLevel, VCP, 리짐 판정)은 자체 설계라 외부 근거가 없다. 주변부만 근거가 있고 핵심부에 근거가 없는 비대칭을 해소하는 유일한 수단이 자체 검증이다.

### 형태: 전략 백테스트가 아니라 이벤트 스터디

포트폴리오 시뮬레이션(체결·슬리피지·자금 배분)은 현 단계에 과하다. 필요한 것은:

1. **리플레이 배치** — 과거 일봉을 날짜순으로 베이스 엔진에 흘려, 판정 전환 이벤트(`READY 진입`, `SUCCESS 판정`, `DOWNSIDE_BREAK`)를 테이블에 적재
2. **전방 수익률 계산** — 각 이벤트에 +5/20/60일 수익률과 동기간 지수 수익률 부착
3. **집계 API** — 시그널 유형별 승률 / 평균 수익 / 분포

### 검증 가설 (베이스 설계 의도.md의 설계 판단 = 검증 가능한 가설)

| 설계 판단 | 검증 질문 |
|---|---|
| VCP는 돌파 직전 응축 신호 | VCP 상태의 돌파가 비VCP 돌파보다 성공률이 높은가? |
| stageLevel 3+는 매도 경각심 구간 | 3단계 이상 진입 후 수익률·최대낙폭이 1~2단계와 다른가? |
| BREAKOUT_READY는 돌파 후보 | READY 중 실제 돌파 비율 / 하방 이탈 비율(거짓 양성률)은? |
| 임계치 10%, 최소폭 15% 등 상수 | 이 값들이 다른 값보다 나은가? ("왜 15인가"에 답) |

### 결과의 서비스 노출

검증 도구는 곧 기능이 된다. **`BREAKOUT_SUCCESS` 판정 시점에 해당 시그널의 과거 성적을 함께 표시:**

> "이 시그널의 과거 성적: N건, 승률 58%, 20일 평균 +6.2% (동기간 코스피 +1.1%)"

검증 결과가 나쁘게 나와도 이득이다 — "검증해봤어요?"라는 질문에 어떤 답이든 데이터로 답할 수 있게 되고, 틀린 부분이 곧 다음 개선 목록이 된다.

## 4. 순위 — "무엇"에 "언제"를 추가

발견 단계의 문제: 목록을 받아도 결국 종목마다 차트를 열어봐야 한다. 시급성 축을 추가한다.

- `BreakoutReadyItem` + **피벗까지 남은 거리(%)** → 근접순 정렬 = "오늘 지켜볼 종목" 순서
- `BreakoutSuccessItem` + **확장도** → 이미 늦은(추격 위험) 종목을 목록에서 식별
- 시그널 과거 성적 한 줄 노출(3번 산출물)

## 5. 회고 — 판단의 데이터화

### 5-1. 스냅샷 지표 자동 동결

스냅샷 생성 시점에 지표 상태를 자동 저장한다. 사용자 추가 입력 없음.

- 동결 항목: regime, stageLevel, 확장도, MA 정배열, RS/FIP/거래량 백분위, **시장 컨텍스트(2번)**
- 저장 구조: 고정 컬럼 대신 `{version, indicators: {...}}` JSON — 지표 추가 시 마이그레이션 불필요
- 인사이트 서비스가 전부 `query(stockCode, at)` 시그니처이므로 **과거 스냅샷 소급 계산(backfill) 가능**. 초기 세트를 완벽하게 만들려 하지 말고, 자리·시장 축이 생기는 대로 추가 + backfill

지표 개수는 12~14개가 상한. 망라가 아니라 **서로 다른 실패 원인을 가리키는 것**이 기준이다: 종목이 좋았나 / 자리가 좋았나 / 시장이 좋았나.

### 5-2. 진입 근거 태그

지표 동결이 "그때 시장이 어땠나"라면, 나머지 반쪽은 "그때 내가 왜 샀나"다. 자유 텍스트와 별개로 근거 태그 선택: `돌파` / `눌림목` / `랭킹 보고` / `뉴스` / `감`.

→ "'감' 매매 승률 32% vs '돌파' 매매 61%" — 어떤 지표로도 얻을 수 없는, 사용자만 아는 데이터.

### 5-3. 판단 성적표

스냅샷 이후 경과 수익률 자동 계산 → "내 BUY 판단의 20일 후 평균 수익률", "지표 상태별 내 승률". **사용자 자신의 기록이 곧 개인화된 백테스트가 되는 구조.**

## 6. 판정 통합 — 하나의 상태와 근거

8개 지표의 종합을 사용자 머릿속에 맡기지 않는다. "매수 추천"이 아니라 **룰의 상태 이름**으로 판정:

```
WATCH → SETUP(응축·피벗 접근) → TRIGGER(돌파, 진입 유효) → EXTENDED(추격 위험) → LATE_STAGE(고단계 분출) → BROKEN(지지 이탈)
```

반드시 근거를 함께 노출:

```json
"reasons": [
  { "rule": "MA_TEMPLATE",   "passed": true,  "actual": "50>150>200" },
  { "rule": "RS_PERCENTILE", "passed": true,  "actual": 87,   "threshold": 70 },
  { "rule": "EXTENSION",     "passed": false, "actual": 13.7, "threshold": 5.0 }
]
```

"8개 룰 중 6개 통과, 확장도에서 탈락" — 블랙박스가 아닌 검증 가능한 시스템.

## 7. 근거 체계 — 지표별 출처 명시

### 7-1. 학술 근거 매핑

| 지표 | 근거 논문 | 핵심 발견 |
|---|---|---|
| Momentum (12개월) | Jegadeesh & Titman (1993), *JF* 48(1) | 승자 매수/패자 매도, 3~12개월 유의한 초과수익 |
| FrogInPan | Da, Gurun & Warachka (2014), *RFS* 27(7) | 연속 정보 모멘텀 5.94% vs 이산 정보 −2.07%. **지표명 자체가 이 논문** |
| MovingAverage | Moskowitz, Ooi & Pedersen (2012), *JFE* 104(2) | 12개월 수익률이 미래 수익의 양(+)의 예측자 |
| Volume | Lee & Swaminathan (2000), *JF* 55(5) | 거래량이 모멘텀의 크기·지속성을 예측 |
| EPS | Bernard & Thomas (1989) — PEAD | SUE 상·하위 스프레드, 48분기 중 41분기 양(+) |
| RS | 횡단면 모멘텀(Jegadeesh–Titman 계열), 실무는 IBD RS |  |

응답에 근거 메타데이터 추가, 화면에는 (i) 아이콘:

```json
"evidence": {
  "grade": "ACADEMIC | PRACTITIONER | PROPRIETARY",
  "source": "Da, Gurun & Warachka (2014), RFS 27(7)",
  "summary": "연속적 정보로 형성된 모멘텀이 이산적 정보보다 지속성이 높다"
}
```

베이스·stageLevel·VCP 축은 실무 전통(미너비니, 오닐, 다바스)으로 `PRACTITIONER/PROPRIETARY` 등급 — **근거 등급을 구분해 표시하는 것 자체가 셀링 포인트**이며, 이 축의 정당화는 3번(자체 검증)이 담당한다.

### 7-2. 주의사항 (근거 확인 중 발견)

- **거래량**: Lee & Swaminathan은 고거래량 승자일수록 **반전이 빠르다**고도 보고. 거래량 급증을 무조건 긍정 신호로 표시하면 근거 논문이 반박 자료가 된다. 돌파 시점 거래량과 상승 지속 중 거래량을 구분할 것
- **EPS**: PEAD의 핵심은 컨센서스 대비 서프라이즈(SUE)이나 현재 구현은 단순 YoY 성장률. 컨센서스 데이터가 없어 SUE 불가한 점을 인지하고, 성장률임을 명시
- **52주 신고가 근접도 추가 검토**: George & Hwang (2004), *JF* 59(5) — 신고가 근접도가 과거 수익률보다 예측력이 높고 장기 반전 없음. 기존 "저항선 돌파" 로직의 학술적 사촌으로, 계산 단순(현재가 ÷ 52주 최고가) + 근거 최상급

## 우선순위

| 순위 | 작업 | 이유 |
|---|---|---|
| 1 | `BaseItem` 확장 (stageLevel·kind·isVcp) | 계산 완료분 노출만, 체감 최대 |
| 2 | 시장 컨텍스트 지표 | 회고 데이터의 전제, 값 2~3개 |
| 3 | 시그널 검증 배치 (리플레이 + 이벤트 적재 + 전방 수익률) | 프로젝트의 논리적 척추 |
| 4 | 스냅샷 지표 동결 + 진입 근거 태그 | 데이터가 쌓여야 가치 — 빨리 시작할수록 이득 |
| 5 | 자리 지표 (피벗·확장도·리스크%) + 랭킹 시급성 축 | 응답 확장 수준, 4번과 병행 시 동결 항목도 풍부해짐 |
| 6 | 검증 결과·시그널 성적의 서비스 노출 | 3번 산출물의 기능화 |
| 7 | 판정 통합 + evidence 메타데이터 | 위 재료들이 갖춰진 뒤의 종합 |

## 페이지별 현재 흐름과 개선

실제 페이지 구조는 세 개다.

```
메인페이지 (랭킹 + 미니차트 + RS·모멘텀·FIP)
   ↓ 종목 클릭
세부종목 페이지 (차트 + 왼쪽 아래 지표들 | 오른쪽 회고 목록·작성)
   ↓ 회고 클릭
회고 페이지 (지표 전체 + 이전 회고 + 새 회고 작성)
```

### 메인페이지 — 고르는 기준을 준다

**현재 논리의 빈틈.** RS·모멘텀·FIP는 전부 "좋은 종목인가"에 답하는데, 랭킹에서 사용자의 질문은 "뭐부터 볼까"다. 질문과 답이 어긋나 있어 위에서부터 하나씩 클릭하게 된다. 시장 상태도 없다.

| 개선 | 내용 |
|---|---|
| 시장 배너 (2번) | 페이지 상단에 지수 MA 위/아래·추세 — 오늘 매수 우호인지 전제 확인 |
| READY + 피벗까지 거리(%) (4번) | 근접순 정렬 = 목록 순서가 "오늘 지켜볼 순서"가 됨 |
| SUCCESS + 확장도 (4번) | "이미 +14% 갔음 = 추격 위험"이 목록에서 바로 보임 |
| 미니차트에 피벗선 1줄 | 이미 있는 간단 차트에 가로선만 추가 — 임박함이 시각적으로 전달 |
| 시그널 과거 성적 (3번) | "이 시그널 승률 58% / 20일 +6.2%" 한 줄 |

### 세부종목 페이지 — 차트·지표·회고를 연결한다

**현재 논리의 빈틈.** 박스는 그려지지만 라벨이 없고(stageLevel·VCP·kind가 응답에서 누락), 지표 8개가 병렬 나열되어 종합은 사용자 머릿속에서 일어난다. 오른쪽에 회고가 나란히 있는 구조는 좋으나 차트와 회고가 서로를 모른다.

**차트 ↔ 지표 연결:**

| 개선 | 내용 |
|---|---|
| 박스 라벨 (1-1) | "2단계 · VCP 응축중" — `BaseItem` 확장으로 해결 |
| 피벗·손절 가로선 + 확장도·리스크% (1-2) | "피벗 대비 +13.7% / 손절까지 -19.6%" |
| 지표를 세 질문으로 그룹핑 | 종목이 좋은가(RS·FIP·모멘텀·EPS) / 자리가 좋은가(regime·stage·확장도) / 시장이 좋은가(신규) — 묶음 자체가 해석 |
| 지표별 (i) 근거 (7번) | 논문 출처 또는 자체 검증 성적 |

**차트 ↔ 회고 연결 (이 페이지의 핵심 개선):**

오른쪽 회고 목록의 각 회고를 **차트 위 시점 마커**로 찍는다. "내가 그때 BUY라고 한 지점"이 캔들 위에 보이면 회고 목록이 글 목록이 아니라 **차트 위의 내 판단 이력**이 된다. 회고 클릭 시 차트가 해당 시점으로 이동. 두 패널이 이미 나란히 있으므로 연결만 하면 된다.

### 회고 페이지 — "그때 vs 지금"을 성립시킨다

**현재 논리의 빈틈.** 이 페이지는 "현재 지표 + 과거 회고 텍스트"를 보여주는데, 과거 회고에 그때의 지표가 없으므로 **비교가 성립하지 않는다.** "그때 2단계였는데 지금 3단계네"라는 문장이 나올 수 없는 구조.

| 개선 | 내용 |
|---|---|
| 작성 시점 지표 자동 동결 (5-1) | 핵심 뷰가 "그때 vs 지금" 대조표가 됨: 단계 2→3, 확장도 +2.1%→+13.7% |
| 이전 회고마다 경과 수익률 (5-3) | "그 후 20일 +8%" 한 줄로 이전 판단 채점 완료 |
| 근거 태그 (5-2) | 작성 폼에 `돌파`/`눌림목`/`랭킹 보고`/`뉴스`/`감` 클릭 2회 |
| 누적 통계 (5-3) | "'감' 매매 승률 32% vs '돌파' 매매 61%", "확장도 10%↑ 진입 승률 33%" |

### 페이지별 대비 요약

| 페이지 | 개선 전 | 개선 후 |
|---|---|---|
| 메인 | 좋은 종목 나열, 볼 순서·시장 상태 없음 | 시장 배너 + 피벗 근접순 + 확장도 + 시그널 성적 |
| 세부종목 | 박스 무라벨, 지표 8덩어리, 차트·회고 단절 | 박스 라벨 + 피벗·손절선 + 3질문 그룹핑 + 회고 시점 마커 |
| 회고 | 현재 지표 + 과거 텍스트 (비교 불성립) | 그때 vs 지금 대조 + 경과 수익률 + 근거 태그 |

한 줄 요약: 메인은 **고르는 기준**, 세부종목은 **차트·지표·회고의 연결**, 회고는 **그때와 지금의 비교**를 다듬는다. 재료(지표 8종, 베이스 엔진)는 충분하며, 개선의 대부분은 새 계산이 아니라 이미 있는 계산을 다음 단계로 넘기는 작업이다.
