# 베이스(`StockBase`) 설계 의도

차트 분석가는 특정 종목이 몇 번째 상승 사이클에 있으며 돌파를 앞두고 있는지를 시각적으로 판단합니다. 이 판단을 코드가 대신 수행하도록 만드는 것이 **베이스(Base)** 의 목표입니다. 베이스는 주가의 저항·지지 구조를 하나의 단위로 묶은 도메인 개념입니다.

이 문서는 베이스를 구성하는 네 가지 기능과, 각 기능을 **왜 도입했는지**를 정리합니다.

---

## 1. 저항·지지의 기록 — `StockBaseLine`

**도입 이유.** 종목이 어느 국면에 있는지 판단하려면 먼저 저항과 지지가 어디에 있는지를 알아야 합니다. 베이스는 그 구조를 기록하는 그릇으로 도입했습니다.

고점(`PIVOT_HIGH`)은 **저항선(RESISTANCE)** 으로, 저점(`PIVOT_LOW`)은 **지지선(SUPPORT)** 으로 기록됩니다. 베이스는 이 라인들을 보관하며 대표값을 항상 최신 상태로 유지합니다.

- **최고 저항선 / 최저 지지선** — 박스의 상·하단 경계에 해당합니다. 새로운 특이점이 통합될 때 갱신됩니다. (`highestResistanceLine`, `lowestSupportLine` / `integratePoints` → `updateHighAndLowLine`)
- **경계 밴드** — 저항·지지 가격에 임계치(%)를 적용한 상·하단입니다. 돌파와 이탈을 특정 가격이 아니라 **허용 오차 범위**로 판단하기 위함입니다. (`StockBaseLinePrice.getUpperBound` / `getLowerBound`)
- **BASE와 PULLBACK의 구분** — 고점·저점의 변동성이 임계치(10%) 이상이면 `BASE`, 미만이면 `PULLBACK`으로 분류합니다. 조정의 깊이에 따라 베이스의 성격을 구분합니다. (`resolveBaseKind`)

---

## 2. 돌파 준비 상태의 선별 — VCP

**도입 이유.** 모든 종목을 대상으로 삼는 것이 아니라, 돌파를 시도할 만한 종목만 선별하기 위해 도입했습니다.

**VCP(Volatility Contraction Pattern)** 는 변동성이 점차 수축하는 패턴입니다. 매물이 소진되고 매수와 매도가 균형을 이루어 돌파 직전의 응축 상태에 진입했다는 신호로 해석됩니다.

- `StockBaseVcp.updateVcp(volatilityHistories)` 는 변동성 이력을 바탕으로 수축 여부를 계산합니다. 이력이 두 개이면 직전 값이 직후 값보다 큰지로, 세 개 이상이면 이동평균 추세의 **기울기가 음수**인지로 판단합니다.
- 이 `isVcp` 값은 리짐 판정의 전제 조건입니다. VCP가 아니면 실시간 판정은 `UNKNOWN`(보류)이며, VCP인 상태에서 현재가가 저항 상단을 상회하면 `BREAKOUT_SUCCESS`, 그렇지 않으면 `BREAKOUT_READY`로 판정됩니다. (`StockRegime.decideRealTimeStockRegime`, `determineDailyRegime`)

---

## 3. 사이클 단계의 계수 — `stageLevel`

**도입 이유.** 종목이 지금 몇 번째 상승 국면에 있는지가 매매 판단, 특히 매도 시점 결정에 직결되기 때문에 도입했습니다.

`stageLevel`은 해당 종목이 몇 번째 상승 국면에 있는지를 나타냅니다.

- 새 베이스가 맥락 없이 생성되거나 하단으로 내려앉는 경우 `init`을 통해 **1단계**가 됩니다.
- 기존 저항을 상향 돌파하여 위쪽에 새 베이스가 형성되면 `upper`를 통해 **현재 단계에 1을 더한 값**이 됩니다. (`StockBaseConfirmer.resolve`)
- 이전 베이스로 회귀하는 등 조정이 필요한 경우 `update(lastBaseStageLevel, …)` 로 단계를 보정합니다. (`StockBaseStageLevelAdjuster`)

`stageLevel`은 단순한 카운터가 아니라 매매 판단에 직결되는 상태값입니다. 3 이상인 구간은 시세 분출이 진행되고 변동성이 확대되는 국면으로, 차익 실현을 준비해야 한다는 경각심 신호에 해당합니다. 낮은 단계는 아직 상승 초기임을 의미합니다.

---

## 4. 사이클 판단의 보호 — 라인 강도와 최강 라인

**도입 이유.** `stageLevel`이 성급한 통합으로 오염되는 것을 막기 위해 도입했습니다. 이 설계에서 가장 직관과 어긋나면서도 중요한 부분입니다.

저항선의 **강도(strength)** 를 측정하여 최고·최저 라인과는 별개로 최강 라인을 추적합니다. (`StockBaseLineStrength`, `strongestResistanceLine` / `strongestSupportLine`, `updateStrongestLines`, `isStrongerThan`)

강도는 **터치 횟수와 누적 거래량**을 로그 스케일로 합산한 값입니다. 동일한 가격대가 여러 차례, 큰 거래량으로 확인될수록 강도가 높아집니다. 신규 라인은 터치 횟수가 0이므로 강도 0에서 출발합니다.

이 지표가 필요한 이유는 통합(병합)을 신중하게 수행하기 위함입니다. 베이스가 여러 개 축적되어 하나는 상단에, 다른 하나는 하단에 위치하는 상황을 가정합니다. 상단 박스가 무너지면 두 베이스를 하나로 통합할지를 판단해야 합니다. 그러나 상단이 일시적으로 붕괴한 것처럼 보이더라도 급반등하는 경우가 빈번합니다. 따라서 가장 강한 라인이 무너지지 않는 한 통합하지 않으며, 통합은 가능한 한 지연시킵니다.

통합을 지연시키는 이유는 `stageLevel`의 오염을 방지하기 위함입니다. 하단으로 통합되면 베이스 구조가 아래쪽으로 재편되면서 `stageLevel`이 낮은 값으로 하향됩니다. 그러나 3단계 이상은 매도를 준비해야 하는 위험 구간의 신호입니다. 실제로는 고단계에 있음에도 성급한 하단 통합으로 단계가 초기화되면, 정작 필요한 시점에 경각심을 전달하지 못합니다.

정리하면 라인 강도 측정은 통합 억제로, 통합 억제는 `stageLevel`의 신뢰도 보존으로, 이는 다시 매도 경각심의 유지로 이어집니다. 강도라는 지표는 결국 잘못된 사이클 단계를 전달하지 않겠다는 하나의 목적을 향합니다.

---

## 코드 매핑

| 설계 의도 | 담당 |
|---|---|
| 저항·지지 기록, 대표 라인 유지 | `StockBaseLine`, `StockBase.highestResistanceLine` / `lowestSupportLine` |
| 경계를 오차 범위로 판단 | `StockBaseLinePrice.getUpperBound` / `getLowerBound` / `isWithinThreshold` |
| 조정 깊이로 베이스 성격 구분 | `StockBase.resolveBaseKind` → `StockBaseKind` |
| 돌파 준비(응축) 판별 | `StockBaseVcp.updateVcp`, `StockBase.isVcp` |
| 돌파 준비/성공 리짐 판정 | `StockRegime.decideRealTimeStockRegime`, `determineDailyRegime` |
| 사이클 단계 계수 | `StockBase.init` / `upper` / `update`, `StockBaseStageLevelAdjuster` |
| 라인 강도 측정 | `StockBaseLineStrength` (터치 횟수·누적 거래량·로그 스케일) |
| 최강 라인 추적을 통한 통합 억제 | `StockBase.strongestResistanceLine` / `strongestSupportLine`, `updateStrongestLines`, `isStrongerThan` |

---

## 요약

베이스는 저항·지지를 기록하고(1), 돌파 준비를 선별하며(2), 사이클 단계를 계수하되(3), 그 단계가 성급한 통합으로 오염되지 않도록 강도로 보호하는(4) 구조입니다. 4번이 없으면 3번의 매도 경각심 신호를 신뢰할 수 없다는 점이 이 설계의 핵심 판단입니다.
